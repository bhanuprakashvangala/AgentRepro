# AI-Generated Code Is Not Reproducible (Yet)

Code and data for **AI-Generated Code Is Not Reproducible (Yet): An Empirical Study of Execution Reliability in LLM-Based Coding Agents**
Bhanu Prakash Vangala, Ashish Gehani, Tanu Malik.
ACM Conference on Reproducibility and Replicability (ACM REP '26), Delft, 2026. [doi:10.1145/3820002.3828581](https://doi.org/10.1145/3820002.3828581)
Repository: [github.com/bhanuprakashvangala/AgentRepro](https://github.com/bhanuprakashvangala/AgentRepro)

An earlier version appeared at the RAI Workshop at AAAI 2026 (Vangala, Adibifar, Gehani, Malik; [arXiv:2512.22387](https://arxiv.org/abs/2512.22387)).

The paper asks whether software written by LLM coding agents runs in a clean environment using only the code,
dependency specification and instructions the agent provides. It covers 300 artifacts generated by Claude Code, Codex
and Gemini Code Assist, 100 per agent: 40 in Python, 35 in JavaScript and 25 in Java. This repository has the prompts,
the generated artifacts, one record per artifact, and a script that rebuilds the paper's tables and figures from those
records.

## Layout

```
data/prompts/     the 100 prompts (p_1-p_40 Python, p_41-p_75 JavaScript, p_76-p_100 Java)
data/results/     one row per artifact: task text, recorded outcome, error label, declared and runtime dependencies
projects/         the generated artifacts, {agent}_generated/{language}/p_N/
src/analysis.py   loading, error categories, Wilson intervals, dependency metrics
src/evaluate_python_project.py   reference implementation of the per-artifact protocol for Python
scripts/reproduce.py             rebuilds the tables and figures and compares them with the paper
results/          paper_values.json, comparison.csv, tables/, figures/
```

In `projects/`, build outputs (`target/`, `node_modules/`, compiled classes and jars), `package-lock.json` files, binary
files (images, PDFs, spreadsheets, SQLite databases), crawled web pages, run logs and `.env` files were removed. Some
folders also contain text files that the code wrote when it ran.

## Setup

```bash
git clone https://github.com/bhanuprakashvangala/AgentRepro.git
cd AgentRepro
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Reproduce

No GPU, network access or API keys are needed; it takes a few seconds.

```bash
python scripts/reproduce.py
```

This rebuilds Tables 2-5 and Figures 3-6 from `data/results/` and writes them to `results/tables/` and
`results/figures/`. It then compares each value with the one printed in the paper (`results/paper_values.json`), saves
the comparison to `results/comparison.csv`, and exits with status 1 if any value differs. Values are compared at the
precision printed in the paper; confidence-interval bounds use a tolerance of 0.1.

The agents are not re-run. Generating artifacts needs the agents' command-line tools and is not deterministic, so the
reproduction starts from the recorded results in `data/results/`. To run one Python artifact through the protocol, use
`src/evaluate_python_project.py` inside a disposable `python:3.10-slim` container (see its docstring).

## Results

All numbers below are produced by `python scripts/reproduce.py`; `results/comparison.csv` lists each one next to the
value printed in the paper. Partial executions count as failures, as in the paper. Intervals are Wilson 95% intervals.

Execution reliability by agent (Table 2):

| Agent | Artifacts | Success | Failed (of which partial) | Rate |
|---|---|---|---|---|
| Claude | 100 | 73 | 27 (4) | 73.0% |
| Gemini | 100 | 72 | 28 (7) | 72.0% |
| Codex | 100 | 60 | 40 (3) | 60.0% |
| Overall | 300 | 205 | 95 (14) | 68.3% |
